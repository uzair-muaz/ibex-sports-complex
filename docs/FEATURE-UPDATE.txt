IBEX Sports Complex — Product Features Overview

For: Client / stakeholders
Purpose: Clear list of what the platform delivers today


1. Overview
-----------

The platform has three parts:

1. Public website — marketing site and court booking
2. Customer account — personal dashboard after login
3. Admin dashboard — staff tools to run the venue

The same backend powers the website and a future mobile app (Flutter), with documented APIs (Swagger).


2. Public website & booking
---------------------------

Website
- Marketing pages for facilities, amenities, membership, contact
- Mobile-friendly layout
- Site navigation: logo left; Home, Book Now, and Sign In (or account avatar) on the right

Court booking
- Choose sport / court type, date, and duration
- Live availability of time slots
- Peak pricing shown clearly
- Past times hidden so customers only see bookable slots
- Apply active discounts at checkout
- Confirmation messaging (including advance payment / 50% policy)
- Email confirmation support

Guest booking (no login required)
- Anyone can book with name, email, and phone
- Booking is saved against their email
- Checkout offers optional sign-in / create account without blocking the booking

Optional sign-in during booking
- Guests are encouraged to sign in to track bookings and earn rewards
- Sign-in is optional today — checkout is not blocked
- “Continue as guest” remains available from the login page when booking

After the visit
- Booking verification page with QR for venue entry
- Feedback form after a completed booking


3. Customer login & account dashboard
-------------------------------------

Sign in / sign up (member access)
- Customers can sign in with Google or email + password
- New customers can create an account with name, email, phone (required), and password
- Forgot password: request a one-hour email reset link (works for Google accounts too, so they can set a password)
- Reset password page completes the link and returns the customer to sign in
- Google-only users can later set a password from My Account so email login works too
- Auth pages use a full-screen branded layout (brand panel + form), with the public navbar; no marketing footer on those pages
- After login, customers land in My Account (staff are redirected to admin)

My Account (sidebar dashboard)
- Dedicated account shell (sidebar + content) — separate from the marketing site chrome
- Sections: Profile, My Bookings, Rewards, Membership, Support

  Profile
  - View and update name and phone
  - Email (from Google or registration)
  - Profile photo when available from Google
  - Set or change password (including for accounts that started with Google only)
  - Automatic link of past guest bookings made with the same email

  My Bookings
  - Upcoming and past bookings in separate lists
  - Booking detail: court, date/time, status, price breakdown
  - See loyalty or membership used on that booking
  - Open verify / QR page
  - Leave feedback when the booking is completed
  - Cancel online if the booking starts in 4+ hours
    - Loyalty points and membership hours are refunded when applicable

  Rewards (loyalty)
  - Points balance and hours played
  - Earn 10 points per hour when a booking is marked completed
  - Redeem at checkout: minimum 100 points, 1 point = PKR 1, up to 50% off (after other discounts)
  - Activity history (earned, redeemed, refunded, adjustments)

  Membership
  - See active plan, hours remaining, guest passes, and expiry
  - Browse available membership packages
  - Purchase today via WhatsApp / offline; venue staff activate the plan
  - Online self-purchase will come later with a payment gateway

  Support
  - Common FAQs (payment, loyalty, membership, cancel)
  - Open a support ticket
  - Reply on open tickets


4. Guest vs logged-in customer (summary)
----------------------------------------

Capability                          | Guest                    | Logged-in customer
------------------------------------|--------------------------|--------------------
Book a court                        | Yes                      | Yes
Sign up / sign in (Google or email) | Can create account       | Already signed in
My Account dashboard                | No (must sign in)        | Yes
Earn & redeem loyalty               | No                       | Yes
Use membership hours                | No                       | Yes
Cancel from account                 | No                       | Yes (within rules)
Past bookings linked after signup   | Yes (by email match)     | Already linked
Forgot / reset password             | N/A                      | Yes (email link)


5. Admin dashboard (staff)
--------------------------

Modern staff UI with light and dark mode.

Access
- Admin / Super Admin only
- Customers cannot open admin; staff are kept in admin
- Staff sign-in page: branded split layout (Operations / Staff console), email + password only

Features
- Bookings — list, search, create, edit, extend, manage payments (cash / online received)
- Courts — manage courts and availability settings
- Users — manage staff / customer accounts as allowed by role
- Discounts — create and manage promotional rules
- Memberships & loyalty — customer roster, activate plans, adjust reward points
- Support — reply to and manage customer tickets
- Feedback — view customer ratings and comments
- Analytics (super admin) — revenue and booking KPIs for chosen date ranges, with clear refresh of stats


6. API & Swagger documentation (requirement)
--------------------------------------------

A single, documented HTTP API is available for the website and mobile app.

- Interactive docs (Swagger UI): available at /docs on the deployed site
- OpenAPI specification: machine-readable API contract for web and Flutter
- Coverage: public booking & courts, customer account, admin operations, mobile Google auth,
  customer register, forgot/reset password, and account password update
- Purpose: client and mobile developers can review and test every endpoint without guessing

This meets the requirement for Swagger / OpenAPI documentation of the product API.


7. Other product improvements
-----------------------------

Operations & trust
- Clear separation of customer vs staff access
- Customer login: Google and email/password; staff: email/password
- Password recovery by email (secure one-hour reset link)
- Faster, more reliable booking availability checks
- Safer handling of membership hours and loyalty points when many people book at once

Analytics
- Dashboard stats are based on daily summaries (not slow full history scans)
- Figures update when bookings change and refresh when staff open analytics

Promotions & payments (venue-side)
- Flexible discount rules
- Track amount received online vs cash on each booking
- Admin tools to confirm and adjust bookings

Quality
- Automated checks and smoke tests to reduce regressions before release


8. Coming later (not in current scope)
--------------------------------------

- Online payment gateway (advance pay / card or local rails)
- Self-serve membership purchase with automatic activation
- Require login before booking (if the venue decides guests should not book)
- Sign in with Apple
- Referral codes for loyalty
- Full redesign of the public marketing site into the admin design system (not required; public site stays branded as-is)


9. Suggested demo flow for the venue
------------------------------------

1. Guest: Book a court without logging in → receive confirmation.
2. Customer: Create an account (email + phone) or Sign in with Google → see claimed bookings →
   book again using points or membership → cancel (if allowed).
3. Password recovery: Forgot password → open email link → set new password → sign in.
4. Staff: Open admin → manage bookings, activate a membership, reply to support, review analytics.
5. API docs: Open /docs → browse Swagger and try sample API calls.
